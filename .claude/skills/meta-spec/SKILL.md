# meta-spec

무엇을 만들지 사람이 한눈에 보는 spec.md를 만든다. 어떻게 만들지는 쓰지 않는다.

## 순서

1. 번호 정하기
   .meta/specs/에서 가장 큰 번호에 1을 더한다. 이름은 영문 소문자 2~3단어. 예: 002-signup

2. 읽기
   contract.md, roadmap.md, 사용자 설명을 읽는다.
   backlog.md에 이 기능 항목이 있으면 읽고 초안에 넣는다.

3. 초안 쓰기
   아래 형식대로 쓴다. 상식으로 채울 수 있는 것은 채우고,
   판단이 갈리는 것만 질문 후보로 남긴다.
   사용자가 하는 주요 동작마다 응답 시간 SC를 둔다.
   contract.md의 품질 기준이 있으면 그것을 쓴다.
   없고 사용자가 따로 정하지 않으면 기본값을 쓴다.
   - 누르거나 입력하면 0.1초 안에 화면이 반응한다
   - 저장, 조회 같은 일반 동작은 0.5초 안에 끝난다
   - 그보다 오래 걸리는 동작은 진행 상태를 보여준다

4. 질문하기 (최대 5개)
   영향이 큰 순서: 범위, 보안, 사용 흐름, 나머지.
   AskUserQuestion으로 하나씩 묻고 추천안을 첫 번째에 둔다.
   답은 해당 항목에 바로 반영한다. 질문 기록은 남기지 않는다.

5. 점검
   언어, 라이브러리, API 이야기가 없는지
   요구사항마다 확인할 방법이 있는지
   성공 기준에 숫자가 있는지
   주요 동작마다 응답 시간 SC가 있는지
   spec이 너무 큰지. 80줄을 넘거나, 서로 따로 써 볼 수 있는 스토리 묶음이 둘 이상이면 크다

5-1. 크면 나눌지 묻기
   "이 spec이 커서 두 spec으로 나눌까요?"라고 묻는다. 어떻게 나눌지 안을 함께 보여준다.
   나누기로 하면 roadmap.md의 기능 순서를 먼저 고치고, 각각 spec을 만든다.
   나누지 않기로 하면 그대로 진행한다.

6. 마무리
   spec-index.md에 이 기능의 상태, 목적, 원본 경로, 사용자 스토리를 추가한다.
   FR과 SC는 넣지 않는다. 형식은 .claude/agents/meta-wiki-writer.md의 spec-index.md 형식을 따른다.
   상태는 "spec 완료"로 쓴다.
   backlog.md에서 이 기능 항목을 지운다.
   다음 단계는 /meta-tech라고 알린다.

## spec.md 형식

```
# 002 회원가입

목적
이메일로 가입해 내 강의를 저장할 수 있게 한다.

사용자 스토리
- P1 이메일과 비밀번호로 가입한다
- P1 가입 직후 바로 로그인된다
- P2 이미 쓰는 이메일이면 안내를 받는다

요구사항
- FR-001 이메일, 비밀번호만 받는다
- FR-002 비밀번호는 8자 이상
- FR-003 같은 이메일은 다시 가입할 수 없다
- FR-004 가입 성공 시 홈으로 이동한다

성공 기준
- SC-001 가입 화면에서 완료까지 1분 이내
- SC-002 잘못된 입력은 모두 이유가 한 줄로 표시된다
- SC-003 가입 버튼을 누르면 0.5초 안에 결과가 나온다

예외 상황
- 네트워크가 끊기면 입력값을 지우지 않는다

범위 밖
- 소셜 로그인
- 이메일 인증
```

## 쓰는 규칙

spec.md가 80줄을 넘으면 먼저 줄여 보고, 그래도 넘으면 5-1의 나누기 질문을 한다.
