# meta-live

외부 서비스를 진짜로 연결해서 확인한다.
개발 중에는 가짜 응답으로만 확인했으니, 배포 전에 실제와 맞는지 본다.
문제를 고칠 때는 원본 문서를 먼저 고치고 코드를 고친다. 결과 기록 파일은 만들지 않는다. 이력은 git으로 본다.

## 순서

1. 키 확인
   .env.example의 변수 이름이 .env에 모두 있는지 본다.
   값은 절대 화면에 보여주지 않는다. 이름만 보여준다.
   빠진 키가 있으면 그 서비스는 건너뛴다고 알리고 계속할지 묻는다.

2. 테스트용 키인지 확인
   실제 돈이 나가거나 실제 데이터가 바뀌는 키면 멈춘다.
   서비스가 테스트 키를 구분하는 방법이 있으면 그걸로 확인한다. 예: test_로 시작하는 키
   구분할 수 없으면 사용자에게 테스트용 키인지 묻는다.

3. 최신 문서 다시 확인
   tests/live/의 파일마다 외부 서비스 하나다.
   서비스마다 meta-researcher 에이전트를 띄운다. 동시에 최대 4개.
   research.md에 적힌 버전 이후 바뀐 점, 응답 모양이 바뀐 점, 곧 없어질 기능을 찾는다.

4. 실제 연동 테스트
   tests/live/만 실행한다.
   호출마다 실제 응답 시간을 잰다.
   spec의 응답 시간 기준을 넘는 호출이 있으면 보고에 함께 보여준다.

5. 문제 나누기
   실패한 테스트와 3번에서 찾은 문서 변경을 아래 종류로 나눈다.

6. 종류별 대응

   키 문제 (예: 401 인증 실패)
   - 고칠 문서와 코드가 없다. 어떤 키가 문제인지 알린다.

   서비스 문제 (예: 503, 429)
   - 고칠 문서와 코드가 없다. 잠시 뒤 다시 실행하자고 알린다.

   모양 다름 (예: 실제 응답에 있는 필드가 가짜 응답에 없다)
   1. 그 기능의 ai/research.md 응답 예시를 실제 모양으로 고친다
   2. 가짜 응답을 고친다
   3. 평소 테스트를 돌려 드러난 실패를 확인한다
   4. src/ 코드를 고친다

   코드 문제 (예: 금액을 문자로 보내 거절당했다)
   1. 규칙이 바뀌었는지 판단한다. 기준은 .claude/meta-rules.md를 따른다
      - 외부 서비스의 규칙이 문서에 없거나 틀렸다: ai/research.md를 먼저 고친다
      - 우리 설계가 없거나 틀렸다: ai/plan.md를 먼저 고친다
      - 문서는 맞는데 코드가 따르지 않았거나, 구현 실수다: 문서는 고치지 않는다
   2. 가짜 응답이 잘못된 요청을 거절하도록 고쳐 문제를 재현한다
   3. 이 문제를 잡는 테스트를 추가하고 실패를 확인한다
   4. src/ 코드를 고친다

   작은 문서 변경 (예: 응답에 필드가 추가됐다)
   - tech.md와 ai/research.md를 고치고 모양 다름과 같이 처리한다.

   큰 문서 변경 (예: API 경로가 바뀌고 예전 경로가 곧 없어진다)
   - 여기서 고치지 않는다.
   - roadmap.md에 새 기능으로 올리고 /meta-spec부터 시작하자고 제안한다.

   동작이 바뀌어야 하는 경우
   - spec.md는 사용자가 허락할 때만 고친다.

7. 마무리 테스트
   고친 것이 있으면 회귀 테스트를 돌린다. 프로젝트 전체에 test, typecheck, lint를 실행하고 tests/live/는 뺀다.
   그다음 tests/live/를 한 번 더 돌린다.

8. 커밋
   커밋 메시지에 무엇을 왜 고쳤는지 쓴다.
   예: "fix: 토스 결제 승인 응답에 approvedAt 반영. 실제 응답과 가짜 응답이 달랐음"
   이미 완료된 기능의 문서를 고쳤으면 /meta-wiki를 다시 돌리라고 알린다.

9. 정리
   테스트가 만든 데이터는 지운다. 예: 테스트로 만든 계정

10. 보고
   서비스별 통과, 실패, 건너뜀 개수와 종류별 대응 결과를 화면에 보여준다.
   건너뛴 서비스는 실제로 확인되지 않았다고 분명히 알린다.

## 보고 예시

```
실제 연동 테스트 결과

Supabase   통과 5, 실패 0, 건너뜀 0
토스페이먼츠 통과 3, 실패 0, 건너뜀 0 (1개 고침)
Resend     건너뜀 3, RESEND_API_KEY 없음. 실제로 확인되지 않음

고친 것
- 토스 결제 승인: 모양 다름. research.md와 가짜 응답, 코드 수정 (커밋 a1b2c3d)

느린 호출
- Supabase 강의 목록 조회: 평균 1.2초. SC-002 기준 0.5초 넘음

제안
- 토스 취소 API 경로가 2026-12에 바뀜. roadmap에 새 기능으로 올리기
```
