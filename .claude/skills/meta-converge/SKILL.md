# meta-converge

구현이 spec대로 됐는지 확인한다.
부족한 것은 tasks.md 5단계에 할 일로 추가한다.
추가한 할 일은 /meta-tdd, /meta-implement를 다시 거쳐 처리한다. 0개가 될 때까지 반복한다.

## 네 가지 분류

- 빠짐: spec이나 plan에 있는데 코드가 없다
- 덜 됨: 코드는 있는데 일부 경우가 빠졌다. 예: 성공만 되고 오류 처리가 없다
- 어긋남: 코드가 spec과 다르게 동작한다. 예: spec은 8자 이상인데 코드는 6자
- 요청 안 함: spec과 plan에 없는 기능이 코드에 있다. "범위 밖" 항목을 만든 것도 여기다

## 순서

1. 회차 확인
   tasks.md 5단계에 있는 "수렴 추가 (N회차)" 제목을 센다. 이번 회차는 N+1이다.
   이전 회차에 체크 안 된 할 일이 남아 있으면 멈추고 /meta-tdd를 먼저 하라고 알린다.

2. 범위 정하기
   잠금 태그 lock/{기능 번호}부터 지금까지 이번 기능에서 바뀐 파일을 찾는다.

3. 검사 (meta-converger 에이전트)
   새 에이전트에게 맡긴다. 구현 과정의 대화는 넘기지 않는다.
   넘길 것: spec.md, plan.md, tasks.md, 바뀐 파일 목록
   돌려받을 것: 네 가지 분류의 목록

4. 사용자에게 물을 것
   어긋남: spec이 맞는지 코드가 맞는지 묻는다.
   요청 안 함: 지울지, 남기고 spec에 추가할지 묻는다.
   spec.md는 사용자가 허락할 때만 고친다.

5. 결과에 따라
   할 일이 0개
   - spec-index.md 상태를 "converge 완료"로 바꾼다.
   - 다음 단계는 /meta-wiki라고 알린다.

   할 일이 있고 이번이 1~3회차
   - tasks.md 5단계에 "수렴 추가 (N회차)" 제목을 만들고 할 일을 추가한다.
   - 빠짐, 덜 됨, 그리고 고치기로 한 어긋남과 요청 안 함을 넣는다.
   - spec-index.md 상태를 "converge N회차"로 바꾼다.
   - 다음 단계는 /meta-tdd라고 알린다.

   3회차를 마쳤는데도 할 일이 남음
   - 할 일을 추가하지 않고 멈춘다.
   - 남은 항목을 사용자에게 보여주고 어떻게 할지 묻는다.

6. 알리기
   사용자에게 분류별 개수와 추가한 할 일 개수만 알린다.

## 할 일 형식

```
## 5. 수렴 추가 (1회차)
- [ ] T020 [덜 됨] [signup-service] 네트워크 오류일 때 입력값 유지
  - 근거: spec 예외 상황
  - 위치: src/features/signup/service.ts:42
  - 이유: 네트워크 오류 때 폼이 초기화된다
- [ ] T021 [어긋남] [schema] 비밀번호 최소 길이를 8자로
  - 근거: FR-002
  - 위치: src/features/signup/schema.ts:7
  - 이유: 코드는 6자 이상을 허용한다
```

두 번째 대괄호는 레인 이름이다. meta-tdd와 meta-implement가 이걸 보고 레인별로 나눈다.

## 사용자에게 보이는 결과 예시

```
수렴 검사 결과 (1회차)
빠짐 0, 덜 됨 1, 어긋남 1, 요청 안 함 0
tasks.md 5단계에 할 일 2개를 추가했습니다.
다음 단계: /meta-tdd
```
