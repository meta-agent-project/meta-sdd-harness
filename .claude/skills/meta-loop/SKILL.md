# meta-loop

나는 지휘자다. 직접 문서나 코드를 쓰지 않는다.
다음 할 일을 찾고, 일꾼을 띄우고, 질문을 전하고, 결과 한 줄만 확인한다.
기억은 파일에 둔다. 상태는 spec-index.md, 할 일은 tasks.md, 이력은 git이다.

## 시작

1. 확인
   roadmap.md가 비어 있으면 멈추고 /meta-interview를 먼저 하라고 알린다.
   git 저장소가 아니면 멈추고 /meta-init을 먼저 하라고 알린다.

2. 안내
   "끝까지 진행합니다. 휴대폰으로 질문을 받으려면 지금 Remote Control을 연결해 두세요.
    컴퓨터가 절전 모드로 들어가지 않게 해 주세요."

3. 기다리는 시간 정하기
   .meta/loop/settings.md에 지난 설정이 있으면 보여주고 그대로 쓸지 묻는다.
   없으면 묻는다.
   "질문이 생겼을 때 답을 몇 분 기다릴까요? 이 시간이 지나면 Claude와 Codex가 함께 정합니다."
   - 10분
   - 20분
   - 30분
   - 기다리지 않음 (바로 함께 정함. 완전 자동)
   - 직접 입력
   정한 시간을 .meta/loop/settings.md에 적는다.

## 구간

1. 준비 구간: roadmap의 모든 기능에 meta-spec을 먼저 실행한다
2. 구현 구간: 기능 하나씩 tech부터 wiki까지 진행하고 다음 기능으로 간다

## 반복

1. 다음 할 일 찾기
   준비 구간이 남아 있으면 spec이 없는 첫 기능의 meta-spec이 다음 할 일이다.
   준비 구간이 끝났으면 meta-flow의 판단 규칙으로 다음 기능과 단계를 정한다.

2. 일꾼 띄우기
   meta-worker 에이전트를 백그라운드로 띄운다.
   넘길 것: 기능 번호, 실행할 스킬 이름
   완료 알림이 올 때까지 다른 일을 하지 않는다.

3. 결과 보기
   일꾼이 돌려준 한 줄을 본다.
   - 완료: 1번으로
   - 질문 대기: 질문 처리로
   - 실패: 실패 처리로

4. 끝
   roadmap의 모든 기능이 완료면 멈추고 푸시 알림을 보낸다.
   auto-decisions.md와 note.md의 "AI가 발견한 문제"에 새 항목이 몇 개인지 함께 알린다.

## 질문 처리

1. .meta/loop/question.md를 읽는다.

2. 화면 시안 질문이면 시안 페이지를 올린다
   세 시안을 탭으로 넘겨 볼 수 있는 페이지 하나를 Artifact 도구로 비공개 게시한다.
   페이지를 쓰기 전에 artifact-design 스킬을 따른다.
   게시한 링크를 질문에 함께 붙인다.

3. 푸시 알림
   "{묶음 이름} 질문 {개수}개. {N}분 뒤 함께 정합니다"
   기다리지 않음이면 알림을 보내지 않고 바로 6번으로 간다.

4. 대화창에 질문과 선택지를 번호로 보여준다
   선택지 질문 창(AskUserQuestion)은 쓰지 않는다. 시간 제한을 걸 수 없기 때문이다.
   예:
   ```
   003-payment tech 질문
   1번. 결제 서비스로 무엇을 쓸까요?
     1. 토스페이먼츠 (추천)
     2. Stripe
   2번. 영수증 PDF는 무엇으로 만들까요?
     1. pdf-lib (추천)
     2. Puppeteer
   "1번은 1, 2번은 2"처럼 답해 주세요. 20분 뒤에는 함께 정합니다.
   ```

5. 타이머
   설정한 시간만큼 기다리는 명령을 백그라운드로 켠다. 끝나면 알림이 온다.

6. 시간 안에 답이 오면
   답을 원본 문서에 반영하고, question.md를 비우고, 커밋하고, 반복 1번으로 간다.
   일부만 답하면 답한 것만 반영하고, 나머지는 시간이 지난 뒤 함께 정한다.

7. 시간이 지나면
   답하지 않은 질문마다 함께 정하기로 고른다.
   원본 문서에 반영하고, auto-decisions.md에 남기고, question.md를 비우고, 커밋하고, 반복 1번으로 간다.
   타이머가 끝났을 때 이미 처리한 묶음이면 무시한다.

8. 이미 정한 묶음에 늦게 답이 오면
   다시 바꾸지 않고 "이미 무엇으로 정했어요. 바꿀까요?"라고 묻는다.
   바꾸면 원본 문서를 먼저 고치고, 이미 지난 단계가 있으면 어디부터 다시 해야 하는지 알린다.

## 함께 정하기

답을 받지 못한 질문은 모두 이 방식으로 정한다.

1. Claude와 Codex가 각자 선택지의 순위를 매긴다. 서로의 순위는 보여주지 않는다.

2. 둘에게 같은 자료를 준다
   - 질문, 선택지, 질문을 만든 스킬이 적은 추천 이유
   - 판단 근거 문서: contract.md, roadmap.md, 그 기능의 spec.md
   - 화면 시안이면 HTML과 화면 캡처
   판단 기준: 근거 문서에 맞는지, 단순한지, 나중에 바꾸기 쉬운지, 화면이면 쓰기 편하고 다른 화면과 일관되는지

3. 화면 캡처
   Playwright로 시안 HTML을 열어 이미지로 저장한다. 사용자에게 묻지 않는다.

4. Codex 부르기
   codex exec를 읽기 전용(-s read-only)으로 실행한다.
   화면 캡처는 -i로 붙인다.
   마지막 줄에 "순위: 2, 1, 3"처럼 선택지 번호만 답하게 한다.

5. 점수
   선택지가 N개면 1등 N점, 2등 N-1점, 마지막은 1점.
   두 점수의 합이 가장 큰 선택지를 고른다. 동점이면 Claude 순위가 높은 쪽.

6. 기록
   두 순위, 이유, 합계, 고른 선택지를 auto-decisions.md에 남긴다.
   Codex 실행이 실패하면 Claude 순위만으로 정하고 그 사실도 적는다.

## auto-decisions.md 항목 형식

```
## 003-payment tech 질문 (2026-10-07 02:14)
질문: 결제 서비스로 무엇을 쓸까요?
선택지: 1. 토스페이먼츠, 2. Stripe
Claude 순위: 1, 2. 국내 카드 지원, 테스트 모드 무료
Codex 순위: 1, 2. contract의 무료 서비스 원칙에 맞음
합계: 1번 4점, 2번 2점
정한 답: 토스페이먼츠
반영한 문서: .meta/specs/003-payment/tech.md
```

## 실패 처리

같은 기능의 같은 단계가 연속 3번 실패하면
1. spec-index.md의 상태를 "막힘"으로 바꾸고 이유를 적는다.
2. 푸시 알림을 보내고 다시 시도, 건너뛰기, 멈춤 중에서 묻는다.
3. 이건 함께 정하지 않는다. 설정한 시간 동안 답이 없으면 루프를 멈춘다.
   기다리지 않음으로 설정했어도 바로 멈춘다.

다음 기능으로 넘어가지 않는다. 다음 기능은 대부분 앞 기능에 의존하고,
막힌 기능의 실패하는 테스트 때문에 회귀 테스트도 통과할 수 없다.

## 안전장치

일꾼 실행 총횟수가 roadmap 기능 수 × 20을 넘으면 멈추고 알린다.
