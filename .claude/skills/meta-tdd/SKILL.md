# meta-tdd

구현 전에 테스트를 먼저 쓴다.
테스트는 git 태그로 잠가서 구현 단계에서 바뀌면 바로 알 수 있게 한다.

## 순서

1. 확인
   프로젝트가 git 저장소이고 spec/{기능 번호} 브랜치에 있는지 확인한다.
   커밋되지 않은 변경이 있으면 사용자에게 알리고 어떻게 할지 묻는다.

2. 읽기
   ai/tasks.md, ai/plan.md, ai/research.md를 읽는다.

3. 준비 (0단계, 스킬)
   설치와 설정 작업을 한다.
   test, typecheck, lint 실행 이름이 없으면 만든다. 이미 있으면 확인만 한다.

4. 뼈대 (1단계, 스킬)
   plan.md 5번의 타입과 함수를 그대로 만든다.
   함수 안은 비우고 "구현 안 됨" 오류만 던진다.
   tasks.md의 공용 파일 중 뼈대 단계에서 등록할 것을 등록한다.
   타입 검사가 통과하면 커밋한다. 커밋 메시지: "chore: 002-signup 뼈대"

5. 테스트 (2단계, 순서대로)
   레인마다 meta-tester 에이전트를 하나씩 차례로 띄운다. 앞 레인이 끝나야 다음 레인을 띄운다.
   뒤 레인은 앞 레인이 만든 테스트 도우미와 가짜 데이터를 가져다 쓸 수 있다.
   각 에이전트에게 넘길 것
   - 레인 이름과 그 레인의 작업
   - 그 레인 모듈과, mock으로 쓸 모듈의 인터페이스
   - research.md의 테스트 도구 사용법
   - 화면 레인이면 design-tokens.yaml, design-system.md, mockups/mockup.html
   레인 하나가 끝날 때마다
   - 직전 커밋 이후 바뀐 파일이 모두 그 레인이 맡은 tests/ 파일인지 확인한다
   - 범위 밖 파일(특히 src/)이 바뀌었으면 되돌리고 그 레인을 다시 맡긴다
   - 설치가 필요하다고 돌려주면, 그 라이브러리가 tech.md에 있을 때만 스킬이 설치하고 그 레인을 다시 맡긴다.
     tech.md에 없으면 멈추고 /meta-tech로 돌아가자고 알린다
   - 뼈대 수정이 필요하다고 돌려주면 멈추고 /meta-plan으로 돌아가자고 알린다
   - 커밋한다. 커밋 메시지: "test: 002-signup {레인} 테스트"

6. 실패 확인
   모든 테스트를 실행한다.
   모두 "구현 안 됨" 때문에 실패해야 한다.
   import 오류나 문법 오류로 실패하면 그 레인 에이전트에게 다시 맡긴다.
   이미 통과하는 테스트가 있으면 의미 없는 테스트이므로 고친다.
   typecheck를 실행한다. 테스트 코드가 인터페이스대로 함수를 부르는지 확인한다.
   타입 오류가 있으면 그 레인 에이전트에게 다시 맡긴다.

7. 잠금
   남은 변경이 있으면 커밋하고, 지금 커밋에 태그를 단다.
   태그 이름: lock/002-signup
   meta-implement는 이 태그와 비교해 테스트가 바뀌었는지 확인한다.

8. 마무리
   tasks.md의 0~2단계 작업에 체크하고 spec-index.md 상태를 "tdd 완료"로 바꾼 뒤 커밋한다.
   다음 단계는 /meta-implement라고 알린다.

## 수렴 회차일 때

tasks.md 5단계에 체크 안 된 "수렴 추가 (N회차)" 할 일이 있으면 그 할 일만 처리한다.

1. 준비와 뼈대는 건너뛴다.
   인터페이스를 바꿔야 하는 할 일이 있으면 멈추고 /meta-plan으로 돌아가자고 알린다.
2. 할 일의 레인 이름별로 meta-tester 에이전트를 순서대로 띄운다. 레인마다 위 5번처럼 확인하고 커밋한다.
3. 새 테스트는 현재 코드에서 실패해야 한다. 고칠 동작을 정확히 확인하는 테스트여야 한다.
   코드 삭제처럼 테스트로 확인할 수 없는 할 일은 테스트 없이 넘긴다.
4. 태그를 단다. 태그 이름: lock/002-signup-rN
5. spec-index.md 상태를 "converge N회차 tdd 완료"로 바꾸고 커밋한다.
   다음 단계는 /meta-implement라고 알린다.
