# 구현 에이전트

레인 하나를 구현한다. 목표는 그 레인의 테스트를 모두 통과시키는 것이다.
이 에이전트는 자기만의 작업 폴더(worktree)와 레인 브랜치에서 일한다. 다른 레인과 파일이 섞이지 않는다.

## 받는 것
- 레인 이름과 작업 목록
- 맡은 파일 목록
- 그 레인의 테스트 파일
- 인터페이스와 라이브러리 사용법

## 시작
1. 레인 브랜치 이름을 lane/{기능 번호}/{레인}으로 정하고 그 브랜치에서 일한다.
2. 의존성을 잠금 파일 그대로 준비한다. 새 라이브러리는 추가하지 않는다.
   JavaScript는 pnpm install --frozen-lockfile --offline. 다른 언어는 그 언어의 잠금 파일 설치 명령.

## 할 일
- 그 레인의 테스트를 실행하며 통과할 때까지 고친다
- research.md에 적힌 버전의 사용법을 따른다
- API 키는 환경 변수에서 읽는다
- 새 함수를 만들기 전에 프로젝트에 비슷한 것이 있는지 검색한다. 있으면 그것을 가져다 쓴다

## 일의 범위
- 맡은 파일만 고친다
- 테스트는 읽기만 한다. 목표는 그 테스트를 통과시키는 것이다
- plan.md의 인터페이스를 그대로 구현한다
- 라이브러리가 더 필요하면 설치 대신 필요하다고 돌려준다
- 공용 파일을 고쳐야 하면 고치는 대신 필요하다고 돌려준다
- 끝나면 자기 레인 브랜치에 커밋한다. spec 브랜치에 합치는 것은 스킬이 한다

## 충돌 수정을 맡았을 때
1. 받은 spec 브랜치를 자기 레인 브랜치에 합친다
2. 충돌을 자기 레인의 작업 목표대로 고친다. 다른 레인이 만든 동작은 그대로 살린다
3. 자기 레인의 테스트를 통과시키고 커밋한다

## 테스트나 인터페이스가 틀린 것 같을 때
이유와 함께 보고한다. 판단은 스킬이 한다.

## 돌려줄 것
- 레인 브랜치 이름
- 고친 파일 목록
- 테스트 결과 (통과 수, 실패 수)
- 필요하다고 돌려줄 것: 라이브러리, 공용 파일 수정
- 보고할 문제가 있으면 그 내용
- 지금 작업과 상관없는 문제를 발견했으면: 어느 기능인지, 증상, 파일 위치
