# 디자인 일관성 규칙과 검증 범위

- 날짜: 2026-10-07
- 참여: 사용자 + Claude

## 배경
하네스로 화면을 만들어보니 버튼이 20종이 생기고, 화면마다 여백과 네비게이션 넓이가 달랐다.
AI가 90%까지 맞추고 나머지 주관적 판단은 사람이 보는 구조를 원했다.
ChatGPT가 제안한 300줄짜리 규칙은 너무 길고 오버피팅이 우려됐다.

## 핵심 논의
- 원인은 규칙 부족이 아니라 구조였다. 시안마다 CSS를 새로 써서 같은 컴포넌트를 매번 다시 그렸고, 검사는 AI가 코드를 읽고 눈으로 판단했다.
- 글로 쓴 규칙을 늘리는 방식은 지금 실패한 방식의 연장이다. 규칙은 짧게, 확인은 측정으로 한다.
- ChatGPT 안에서는 "안쪽 여백은 부품, 사이 간격은 부모의 gap" 한 줄만 가져왔다.
- 원본은 yaml로 두고, 브라우저가 yaml을 읽지 못하므로 공통 ui.css를 둔다. 시안은 ui.css를 불러온다.
- 새 값이나 새 컴포넌트는 막지 않는다. yaml에 추가하고 ui.css에 반영하는 길로 들어오게 한다.
- 버튼만이 아니라 모든 컴포넌트(입력창, 체크박스, 라디오, 표, 네비게이션 등)에 같은 틀을 쓴다: 용도별 variants, 화면끼리 같아야 하는 same.

## AI가 확인할 수 있는 범위
- 높음: ui.css 클래스 사용, 크기 단계(간격, 글자 크기, 높이, 모서리) 밖의 값, 변형 개수, same 값, 한 줄 컨트롤 높이, 부품 바깥 margin
- 중간: 용도에 맞는 변형인지(삭제는 danger), 글자 역할이 맞는지
- 사람이 봄: 단계 값을 무엇으로 정할지, 위계가 잘 읽히는지, 밀도, 분위기

## 결론
- .meta/design/ui.css를 둔다. 토큰은 CSS 변수, 컴포넌트는 .{컴포넌트}-{변형} 클래스다.
- 크기는 종류마다 5단계 이하다. 글자는 제목, 섹션, 본문, 보조 역할로 나눈다.
- components.yaml에 variants와 same을 쓴다.
- 확인은 시안을 브라우저로 열어 실제 값을 재서 한다.
- 전체 검사 때 모든 화면을 한 장에 모아 사람이 마지막으로 본다.
